# CLAUDE.md

Закрытый мессенджер для узкого круга (3–5 человек). Главное — голосовые/видео звонки с E2E-шифрованием и минимальной задержкой. Текст вторичен. Регистрация только по инвайтам админа. Один сервер, который можно быстро заменить.

Общение с разработчиком: по-русски, коротко, без воды. Идентификаторы, коммиты, комментарии в коде — английский.

## Принципы (нарушать нельзя)

1. **Сервер одноразовый.** Всё критичное живёт на клиентах: ключи, сертификаты, история, исходящая очередь. Потеря сервера = потеря максимум недоставленных сообщений за ≤24 ч, и то только если у отправителя тоже умерло устройство.
2. **Сервер не видит содержимого.** Только зашифрованные блобы, публичные ключи и метаданные маршрутизации. Никаких данных, позволяющих расшифровать трафик.
3. **Медиа идёт P2P.** TURN — только fallback. Серверу незачем участвовать в звонке, если есть прямой путь.
4. **Криптографию не изобретаем.** Только стандартные примитивы из проверенных библиотек (Ed25519, X25519, HKDF-SHA256, XChaCha20-Poly1305). Подписываем сырые байты, никогда не JSON-представление.
5. **Ничего не храним дольше 24 ч и ничего не пишем на диск.** Ящики сообщений только в RAM, без бэкапов. На сервере не должно быть того, что стоит искать: защита в архитектуре, а не в механизмах самоуничтожения (их не делаем).

## Запрещено

- Логировать plaintext, ключи, SDP целиком, токены. В логах сервера — без IP и без идентификаторов пользователей.
- Вшивать в клиент TURN-секрет, FCM/APNs-ключи или любые серверные секреты.
- Добавлять аналитику, крашрепортеры и любые SDK, шлющие данные третьим сторонам (Sentry, Firebase Analytics и т.п.). FCM используем только для пустых wake-up пушей.
- Менять формат протокола без обновления `protocol/` и тест-векторов.

## Стек

- **Клиент:** Flutter (Android, iOS, Windows, macOS, Linux), `flutter_webrtc`, `flutter_callkit_incoming`, крипта через libsodium-биндинги или пакет `cryptography`.
- **Сервер (relay):** Go, один бинарник. WebSocket (`github.com/coder/websocket`), SQLite (`modernc.org/sqlite`) на tmpfs, Ed25519 из stdlib.
- **TURN:** coturn с `use-auth-secret` (временные HMAC-креды).
- **Ingress:** Caddy (авто-TLS, 443).
- **Файрвол:** nftables, SSH за fwknop.
- **ОС сервера:** Debian 13 (trixie), минимальный образ, unattended-upgrades только для security.
- **Управляющая машина:** Windows + WSL. Ansible и Claude Code запускаются только из WSL, ключи лежат в `~/.ssh` внутри WSL.
- **Инфра:** Docker Compose + Ansible, секреты в ansible-vault или sops.
- **Админка:** Go CLI `tools/admin` — ключи, сертификаты, манифест, отзыв.

## Текущий сервер

- Провайдер VDSina, KVM, Debian 13. Адрес — в `infra/ansible/inventory.ini`, в код и документацию не хардкодить.
- Бутстрап сделан вручную:
  - `vegameta` — администратор, вход по ключу, sudo с паролем;
  - `deploy` — для Ansible и Claude Code, отдельный ключ `~/.ssh/deploy_ed25519`, `NOPASSWD` sudo через `/etc/sudoers.d/deploy`;
  - вход по паролю и для root закрыт (`/etc/ssh/sshd_config.d/00-hardening.conf`), пароль root заблокирован.
- Наружу слушает только sshd:22. Файрвола, Docker и fwknop пока нет.
- Инвентарь: `ansible_user=deploy`, `ansible_ssh_private_key_file=~/.ssh/deploy_ed25519`. В WSL настроен SSH-алиас `vpn-srv` (пользователь `deploy`): для диагностики `ssh vpn-srv`.

### Правила работы агента с сервером

- Любые изменения на сервере — только через Ansible, руками только диагностика.
- Всё, что может отрезать доступ (sshd, nftables, fwknop, sudoers), показывать и подтверждать отдельно. Перед применением держать открытой вторую SSH-сессию. После применения проверять вход новым подключением.
- sudoers менять только с проверкой `visudo -c`, sshd — с `sshd -t` перед reload.
- Резервный доступ — VNC-консоль в панели VDSina. Буфер обмена там ненадёжен, длинные строки (ключи) через неё не вводить.

## Идентичность и инвайты

- Админ держит **корневой ключ Ed25519** (офлайн, зашифрован, минимум две резервные копии). Его публичная часть вшита в клиент. Потеря ключа = нельзя выдавать инвайты и переезжать на новый сервер.
- Устройство при первом запуске генерирует свою пару ключей (Ed25519 для подписи, X25519 для шифрования) и показывает публичную часть QR-кодом.
- Админ подписывает **сертификат**: `{user_id, name, sign_pub, enc_pub, issued_at, expires_at}`.
- Клиент принимает сообщения, сигналинг и звонки только от держателей валидного неотозванного сертификата. Проверка локальная.
- v1: одна личность = одно устройство. Мультидевайс — открытый вопрос (см. ниже).

## Манифест (ключ к бесшовной замене сервера)

Один подписанный админом документ:

```
{ version (монотонный), issued_at,
  servers: [{ url, ip_fallback, server_pub }],
  stun: [...], nostr_relays: [...],
  revoked: [user_id, ...] }
```

- Клиент принимает манифест только с валидной подписью админа и `version` больше текущей.
- Каналы распространения (клиент проверяет все при недоступности сервера): встроенный в сборку, `GET /manifest` на сервере, replaceable-событие в Nostr, статическое зеркало (Pages/gist). Чем больше независимых каналов, тем лучше.
- У сервера своя пара ключей. Клиент при подключении проверяет, что сервер владеет `server_pub` из манифеста (challenge-response поверх TLS). Подменённый сервер не пройдёт.

## Сервер: API

Аутентификация: сервер шлёт nonce → клиент подписывает `nonce || server_pub` ключом устройства и прикладывает сертификат → сервер проверяет подпись админа и список отзыва.

WebSocket `/ws`, фреймы:
- `send {to, id, blob}` — положить в ящик получателя. Ответ `stored {id}`.
- `deliver {id, blob}` — сервер отдаёт получателю (онлайн — сразу, иначе при подключении).
- `ack {id}` — получатель подтвердил, сервер удаляет.
- `signal {to, blob}` — сигналинг звонка. Не пишется в БД. Если получатель офлайн: wake-up push + удержание в памяти ≤60 с.

HTTP: `GET /manifest`, `POST /turn-credentials` (TTL 2 ч), `POST /push-token`.

Лимиты: блоб ≤64 КБ (вложения вне v1), квота на отправителя, rate limit.

## Файрвол и SSH

nftables, входящие по умолчанию `drop` (молча, без reject). Первое правило — `ct state established,related accept`. Исходящие открыты (FCM, APNs, Nostr, apt).

| Порт | Что | Доступ |
|---|---|---|
| 443/tcp | Caddy → relay (WS, `/manifest`, `/turn-credentials`) | всем |
| 3478/udp+tcp | STUN/TURN | всем |
| 5349/tcp | TURN over TLS | всем |
| 49160–49299/udp | relay-порты coturn (`min-port`/`max-port`) | всем |
| 22/tcp (или другой) | SSH | только IP, прошедшему knock |
| ICMP | PMTU, ICMPv6 ND | нужное для работы сети |
| остальное | — | drop |

- Relay-диапазон «активный»: порты открыты в файрволе, но coturn пересылает только для аутентифицированных аллокаций с выданными permission, остальное дропает. Для 3–5 человек хватит сотни портов.
- Настройки coturn: `denied-peer-ip` на приватные диапазоны (10/8, 172.16/12, 192.168/16, 127/8, fc00::/7, ::1) против SSRF во внутреннюю сеть, `no-multicast-peers`, `no-cli`, `no-tlsv1`, `no-tlsv1_1`.
- SSH: только ключи, `PasswordAuthentication no`, `PermitRootLogin no`. Порт закрыт, открывается `fwknop` (SPA: один пакет с HMAC, не повторяется, в отличие от последовательности портов) для IP стучащего на 30 с. Дальше сессия живёт через conntrack. Резервный доступ — веб-консоль VPS-провайдера.
- Ansible стучит в `pre_tasks` (`delegate_to: localhost`). На свежем VPS SSH открыт до конца первого прогона, файрвол включается последним шагом.
- **Docker обходит nftables** для опубликованных портов (пишет свои правила в iptables). Поэтому coturn запускаем с `network_mode: host` (к тому же публиковать сотню UDP-портов через docker-proxy медленно), relay не публикуем наружу вообще (только внутренняя сеть до Caddy), Caddy публикует только 443. Проверять после деплоя сканом снаружи.
- TLS: Caddy получает сертификат через TLS-ALPN-01 на 443, порт 80 не нужен.

## Что остаётся на сервере

- БД ящиков — на tmpfs (`tmpfs: /data:size=256m,mode=0700` в compose). Перезагрузка стирает всё. Это безопасно: отправители держат сообщения в outbox до E2E-квитанции и переотправят.
- Своп выключен (`swapoff -a`, убрать из fstab), иначе RAM утекает на диск.
- Логи: relay пишет только ошибки без IP и ID. Caddy без `log`-директивы (access-лога нет). coturn: `no-stdout-log`, `log-file=/dev/null`. journald: `Storage=volatile`.
- На диске только: ключ сервера, TURN-секрет, FCM/APNs-ключи, конфиги. Всё это ротируется при каждом переезде.

## Жизненный цикл сообщения

1. Отправитель шифрует: эфемерный X25519 → HKDF → XChaCha20-Poly1305. Внутри шифротекста — подпись отправителя. `id` = случайные 128 бит.
2. Кладёт в **локальный outbox** и отправляет на сервер.
3. Сервер хранит блоб, `expires_at = now + 24h`. Раз в минуту удаляет просроченное.
4. Получатель забирает → `ack` серверу (сервер удаляет) → дедуплицирует по `id` → шлёт отправителю **E2E-квитанцию** (обычное маленькое сообщение).
5. Отправитель удаляет из outbox **только по E2E-квитанции**, а не по `stored` от сервера.
6. Нет квитанции за 24 ч → статус «не доставлено», повтор вручную.

Из-за шага 5 смерть сервера не теряет сообщения: outbox переотправляется на новый сервер, дубликаты отсекаются по `id`.

v2: заменить схему на Double Ratchet (vodozemac, Apache-2.0) ради forward secrecy.

## Звонки

- Сигналинг: основной канал — WS сервера. Fallback — Nostr-релеи (события зашифрованы на ключ получателя).
- Все SDP подписываются ключом устройства. DTLS-fingerprint из SDP сверяется с подписью → MITM на сигналинге не проходит. Опционально SAS-код на экране.
- ICE: публичные STUN + свой TURN (UDP 3478, TLS 5349). `iceTransportPolicy: all`, прямой путь в приоритете.
- Смена сети (Wi-Fi ↔ LTE): ICE restart без разрыва звонка.

### Аудио-режимы (переключаются во время звонка)

| | Голос (по умолчанию) | Чистый звук |
|---|---|---|
| AEC / NS / AGC (софт) | вкл | выкл |
| Системная обработка (Android HW AEC/NS, iOS voice processing) | вкл | выкл |
| Opus | моно, ~32 кбит/с, DTX вкл | стерео, ~128 кбит/с, DTX выкл |
| FEC | вкл | вкл |

- Переключение: новый трек с другими констрейнтами → `sender.replaceTrack()`, битрейт через `setParameters`. Без пересогласования.
- `stereo=1` в fmtp Opus согласовывается сразу при установке звонка, иначе стерео потом не включить.
- В UI предупреждение: «Чистый звук» только в наушниках, иначе эхо.

## Отказ сервера

| Что работает без сервера | Что нет |
|---|---|
| Уже идущие P2P-звонки | Звонки через TURN (обрываются, клиент пробует ICE restart напрямую) |
| Новые звонки, если оба в приложении (сигналинг через Nostr, только STUN) | Входящие на спящий телефон (нет push) |
| Локальная история и outbox | Доставка текста (копится в outbox) |

Поведение клиента:
- WS упал → backoff-переподключение. После ~1 мин неудач — режим «сервер недоступен»: сигналинг через Nostr, баннер в UI, опрос всех каналов манифеста раз в несколько минут.
- Новый манифест → подключение к новому серверу → auth → регистрация push-токена → переотправка outbox.

Процедура замены (цель ≤15 мин):
1. Новый VPS: **сразу при создании в панели указать SSH-ключ** → `bootstrap.yml` под root (пользователи `vegameta` и `deploy`, sudoers, `00-hardening.conf`, блокировка root) → `deploy.yml` (Caddy + relay + coturn + nftables + fwknop, tmpfs, своп выключен).
2. **Ротация при каждом переезде:** новый ключ сервера генерируется на новом VPS (Ansible забирает публичную часть), новый TURN-секрет, новый FCM/APNs-ключ (старый отозвать в консоли Google/Apple). Секреты старого сервера никуда не переносятся.
3. `tools/admin manifest bump` с новым `server_pub` и адресом → опубликовать во все каналы.
4. Если домен жив — после публикации манифеста поменять A-запись (TTL 60 с). Клиент со старым манифестом увидит несовпадение ключа, подтянет манифест с зеркал и переподключится. Итого секунды.

Переносить с сервера на сервер нечего: БД эфемерная, секреты новые.

## Push

- Android: FCM data-only, пустой payload («проснись и подключись»). Google видит только сам факт пуша.
- iOS: VoIP PushKit → обязательный `reportNewIncomingCall` в CallKit.
- Десктоп: без push, фоновое WS-соединение.

## Этапы

1. Два клиента, ручной копипаст SDP → P2P-звук.
2. Ключи, подпись SDP, проверка fingerprint.
3. `tools/admin`: корневой ключ, сертификаты, манифест.
4. Go relay: auth, signaling, mailbox с TTL. Compose + coturn + Caddy.
4a. `bootstrap.yml` (повторяет ручной бутстрап) и `deploy.yml`. Базовая роль: удалить `qemu-guest-agent` и `haveged`, замаскировать `systemd-ssh-generator` (`/etc/systemd/system-generators/systemd-ssh-generator → /dev/null`), выключить своп, journald volatile, unattended-upgrades. Затем Docker, nftables, fwknop — последним. Проверка открытых портов сканом снаружи.
5. Текст по схеме outbox/квитанций.
6. Аудио-режимы.
7. Push + CallKit.
8. Fallback через Nostr, сценарий отказа сервера, прогон процедуры замены вживую.

## Открытые вопросы

- Мультидевайс: сертификат на пользователя со списком устройств или отдельный сертификат на устройство?
- TURN на 443 (отдельный IP или SNI-роутинг) для сетей, где режут всё, кроме 443.
- Автоповтор сообщений после истечения 24 ч или только вручную.
- Устройства без Google-сервисов (UnifiedPush?).
- Метаданные: сервер видит, кто кому пишет. Sealed sender — после v1.
